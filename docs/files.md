# What each file is

What [the plan](plan.md) describes, as code that runs. The design on one page, with a complete example, is
[design.md](design.md). `src/` is the package; `checks/` holds it to what it says; `examples/` are parts of apack
ported to it; `measure/` prints what things cost; `surveys/` read an apack checkout; `tools/` read states' types.

| File | What it is |
|---|---|
| `docs/guarantees.md` | The four lifetimes, atomicity, cancellation, handle semantics, and the trusted-host boundary |
| `docs/deferred/` | What is left out of the plan on purpose, each with what it is, what it would take, and what would make it worth starting |
| `src/index.ts` | The door: every export of the package, by name |
| `etc/*.api.md` | What each entry offers, as API Extractor reads it: `npm run api:check` holds the source to them, `npm run api:update` writes them |
| `.github/pull_request_template.md` | What a pull request says: what holds, how it is known, the mutants, and what is the owner's to decide |
| `.github/workflows/packages.yml` | Packs each `master` commit whose CI passed and publishes it as the prerelease `pkg-<commit>` |
| `scripts/package-smoke.mjs` | Installs the packed package into a project of its own, imports each entry and runs a state from it |
| `scripts/workflows-check.mjs` | Fails a workflow or package script that could publish to npm or hold a token for it |
| `scripts/deps.mjs` | The siblings' packages this repository installs, and where each comes from: `deps:pin`, `deps:local`, `deps:released`, `deps:check` |
| `scripts/package-lint.mjs` | Packs the package and runs publint and attw (`esm-only`) over the tarball |
| `.oxlintrc.json` | oxlint's rules: its defaults, less those whose findings here are deliberate |
| `scripts/api.mjs` | Writes or checks those reports, from declarations emitted afresh from the source |
| `src/types.ts` | The types a state's code is checked against: its shape, its definition, what a handler is handed and may return, and how one state reaches another |
| `src/kernel.ts` | The kernel: systems, steps, asks, and the port boundary between a backend and its windows |
| `src/port.ts` | What one system offers another across a link (`Port`, `PeerPort`, `Following`, `Failure`, `PortOutcome`), a schedule's `Lane`, and a system's structural `Clock` |
| `src/draft.ts` | Data edited in place, from which a new value is made. What the kernel uses for a nested change |
| `measure/append-cost.mts` | What a growing list costs one change at a time and in batches, on the draft and through an ask. Runs, for about 25 seconds |
| `measure/frozen-cost.mts` | What a frozen list costs to read and to copy, beside the same list unfrozen. A measurement: it prints, and refuses nothing |
| `src/mirror.ts` | A running state as a value a component reads: each field is the state's own object, never copied or wrapped, written when the state replaces it. One mirror for each state, shared by all that read it |
| `src/vue.ts` | `useState`: what a Vue component uses to read a running state and tell it things |
| `checks/vue-check.mts` | `useState` checked by rendering real components with Vue's runtime and counting what rendered, as render functions and as compiled templates. Runs |
| `type-tests/*.ts` | What must not compile, by topic: data that cannot be written, answers, follows, loads, calls, arms, starts, who may send what, refusals and `within`. Each `@ts-expect-error` is a case; `npm run typecheck` fails on one whose line compiles. Compiled, never run |
| `docs/errors.md` | What a compile error means: each type test's mistake, what TypeScript says of it, and why. Generated by `npm run errors:update`, held to the compiler by `npm run errors:check` |
| `scripts/errors.mjs` | Writes or checks `docs/errors.md`, compiling the type tests with their directives blanked out |
| `type-tests/vue-templates/` | A component file with a template, and the states it reads, for `vue-tsc` to check: what a template may read, and six lines that have to be errors |
| `src/window-frame.ts` | What a frame is in a window: the next paint while it shows, the next turn while it is hidden |
| `checks/progress-check.mts` | That progress is gathered and nothing else is, and that what a state hears keeps the order it was sent in. Runs |
| `src/testing.ts` | `@apackdev/state/testing`: the schedule of `@apackdev/orderings` (`everyOrder`, `explore`, `sample`, `replay`, its clock), `connect(window, backend, schedule?)` over `@apackdev/link`, a system on a schedule (`onSchedule`), and scenarios made from the events a state declares (`fromEvents`) |
| `checks/log-check.mts` | A step's log: what began it, what changed, what left, how it ended, that nothing carried is in it, and that what was stale when its turn came is not in it |
| `checks/clock-check.mts` | A system's clock: step-stamped `now` in handlers and logs, live `now` after an `await` in work, monotonic clamping, no-clock refusals, and `sleep(ms)` cancellation under every ordering. Runs |
| `checks/peers-check.mts` | Named non-window peers: `peer(name, peer)`, `tell({ peer }, event)` commit-time delivery, `outcome: 'dropped'` logging, `safely` isolation, and no view hold over `@apackdev/link` under every ordering. Runs |
| `checks/brain-check.mts` | A slice of apack's brain: dynamic trigger nodes via one declared `TRIGGER` event, recursive subflows, commit-time `runHistory` peer facts with `now`, `sleep(ms)` delays, and `KILL_BRAIN` cancellation under every ordering. Runs |
| `checks/testing-check.mts` | That kit, held to what it says |
| `src/turn.ts` | The next turn of the event loop, in Node and in a window: what the kernel puts off with when it is given nothing, and what every check waits a turn with |
| `checks/interleaving-check.mts` | Scenarios run under every ordering: a search over a search, a cancel, a click among progress, a window closing. Runs, for about 7 seconds |
| `examples/commit.mts` | A slice of the app's commit surface ported: its status and a diff as reads it loads, staging and a push as writes it calls. Runs, and checks what each step leaves |
| `checks/internal-check.mts` | Who may send a state what: the events it raises reach it from nowhere else, and one surface tells another in its window. Runs |
| `checks/loads-check.mts` | The reads a state loads: from the fields it names, one for each key of a field, or one for each key read again from fields, under every order a read asked again can end in; and that what one delivers once it is no longer awaited takes no step. Runs |
| `checks/calls-check.mts` | The writes a state calls: fired once with `call`, with pending state kept by the kernel; and that what one delivers once it is no longer pending takes no step. Runs, for about 10 seconds |
| `checks/arms-check.mts` | Imperative timers declared under `arms`: `single` and keyed `each`, a duration declared as `after` or given at `arm`, `whenArmed: 'restart'`/`'ignore'`, optional `expired`, `arm`/`disarm` rollback, exit cleanup, Vue mirror reactivity, and `explore` determinism. Runs |
| `checks/checks.mts` | What every check file is written with: each check becomes a vitest case with its own name, each system a check makes is stopped however it ends and given a limit on its steps, and `rest()` waits until what the check started has come to rest |
| `checks/examples-check.mts` | Runs each example that runs, as a case of its own |
| `checks/starts-check.mts` | The states a state starts: declared, and which of them run follows from its data. Runs |
| `checks/follows-check.mts` | The views a state follows: declared, and which are followed, and what each is asked for, follow from its data, from fields, for each key of a field, or both; and that an update of one no longer followed takes no step and hands nothing over. Runs |
| `checks/answer-check.mts` | An ask that changes something as it answers: the change is there with the answer, a refused change fails the ask, nothing is lost across a wait. Runs |
| `checks/unsaid-check.mts` | What a handler said when it was not made: one that threw, refused, or returned a change that could not be made has told, sent, asked and broadcast nothing, on a backend and in a window. Runs |
| `checks/failure-check.mts` | What happens when a state's work or a handler throws: where the state goes, and that the kernel goes on. Runs |
| `checks/leaving-check.mts` | What happens to an ask when whoever made it goes: it throws `Cancelled` where awaited, `finally` runs, the answerer is told, nothing hangs. Runs |
| `checks/store.mts` | Rows as the rule about them is checked: one interface, and rows kept in memory behind it. `transact` is all the kernel is given of it |
| `checks/store-elmdb.mts` | The same interface over the app's engine, elmdb, on a temporary database. Needs the checkout's dependencies |
| `checks/rows-check.mts` | A step as one unit of the database: a handler's rows, data and what it sent kept together, on both stores. Runs, for about 12 seconds |
| `checks/rows-property.mts` | The same rule as a property: runs of handlers made from a seed, held against a model of a few lines, one after another and under way together. Runs, for about 25 seconds, and names the seed of a run that differs |
| `checks/views-check.mts` | A window hears of a step after its views show it: views over the link, and what a step sends windows held until they have been sent its rows. Under every ordering in memory, and on elmdb. Runs, for about 10 seconds |
| `src/graph.ts` | `@apackdev/state/graph`: static TypeScript graph analyser (`analyseGraphs`, `formatGraphs`, `runGraphCli`) supporting `--tsconfig` and return-type `State` detection |
| `src/inspect.ts` | `@apackdev/state/inspect`: zero-dependency, browser- and Node-compatible unified causal inspector (`createInspector`, `formatCausalTrace`) over `StepLog`, `Defect`, and `StateGraph` |
| `checks/inspect-check.mts` | The causal inspector held to cross-system stitching, `explain()`, `inFlight()`, `whyIgnored()`, `coverage()`, ring-buffer eviction, snapshots, formatting, and payload-free JSON export |
| `bin/apack-state-graph.mjs` | Packaged CLI entrypoint (`apack-state-graph [--tsconfig <path>] <file...>`) |
| `checks/refusals-check.mts` | What the compiler says of a definition it refuses, read whole: the reason for each rule that gives one, which `docs/errors.md` shows only the start of. Compiles small definitions with TypeScript. Runs |
| `checks/graph-check.mts` | The graph tool (`@apackdev/state/graph` and `tools/graph.mts`) run on hard-to-read states, non-`state` aliases (`hostState`, inline `forNet`), custom `--tsconfig` path aliases, CLI errors, and what cannot happen: which states are never entered and which timers nothing arms, each said once by its cause, each kind of handler by whether its state can be the case, and each kind of thing that cannot be read hiding what it could do from where it is and nothing else |
| `checks/graphs/*.mts` | Small state fixtures for `checks/graph-check.mts` (`child-entered-first.mts`, `written-short.mts`, `keyed-from.mts`) |
| `checks/mutants-check.mts` | Holds `scripts/mutants.mjs`, `scripts/mutants-list.mjs`, and `scripts/mutants-merge.mjs` to range pruning, allowlist updating, and entry-level merging |
| `checks/master-status-check.mts` | Holds the CI master-status issue-management logic to opening, updating, and closing failure issues cleanly |
| `vitest.config.mts`, `vitest.mutants.mts` | Vitest configurations for the Node and Chromium browser projects and for Stryker mutation runs |
| `stryker.config.mjs` | Stryker mutation testing configuration (`MUTATE` sharding, `perTest` coverage analysis, timeouts) |
| `checks/link-check.mts` | A backend and a window joined directly by `@apackdev/link` on their ports with no adapter and one hold owned by the link, held to what a window is promised: answered and told after its view shows the step, under a seed's worth of orderings of the two packages; a link that goes ends what was asked as disconnected, and the backend goes on |
| `measure/compile-cost.mts` | What TypeScript takes to check 10, 100 and 300 generated states, each as a pack writes one: check time, wall time, types and memory. A measurement |
| `measure/record.mts` | What a measurement records beside what it prints, for `npm run bench` |
| `scripts/mutants.mjs` | Reads a mutants run's reports and fails on a survivor not in `mutants.allowed.json`, or (`--all`) an entry that survives in none |
| `scripts/mutants-list.mjs` | Writes `mutants.allowed.json` from a run's reports: stale entries off, survivors on with an empty why to fill in (`npm run mutants:list`) |
| `scripts/mutants-merge.mjs` | Merges `mutants.allowed.json` entry by entry as a git merge driver, once `npm run mutants:merge-install` sets it up |
| `scripts/mutants-names.mjs` | How a mutant is named in the list, and which of a report's mutants survived |
| `scripts/pre-push.mjs` | What runs before a push: lint, typecheck, API reports, specs, and mutants in the files under `src/` the branch changed |
| `scripts/hooks-install.mjs` | Has git run it before each push from this checkout, if asked to: `npm run hooks:install` |
| `scripts/bench.mjs` | Runs every measurement, prints each reading beside the recorded one, and records them with their conditions (`--record`) |
| `bench/*.json` | The recorded readings: each measurement's, with the date, commit, machine, load, Node and elmdb they were read under |
| `measure/hold-stall.mts` | What the hold costs a window under a steady stream of writes, twelve views each touched in turn, for the hold as it was and as it is. A measurement: it prints, and refuses nothing |
| `measure/rows-cost.mts` | What a unit around a step and around each handler costs on elmdb, beside the engine alone, and what holding an answer for the views costs a window. A measurement: it prints, and refuses nothing |
| `surveys/writes-survey.mts`, `surveys/writes-shape.mts` | Where the app writes to the database, and how each function that writes does it, read from syntax trees. Each takes the checkout to read |
| `checks/binding-check.mts` | That a reader is handed the state's own values and runs when a field it read is replaced, that none of it can be written, and that a hidden window still hears. Runs |
| `checks/kernel-check.mts` | What the kernel does with a change to data, a move that edits a draft and the refused edits included. Runs |
| `checks/draft-check.mts` | The checks a hand-built draft has to pass. Runs |
| `examples/search.mts` | The app's code search, backend and surface, ported. Runs, and checks what each step leaves |
| `examples/brain.mts` | A slice of the app's brain ported: recursive flows and subflows, dynamic triggers via one declared `TRIGGER` event, `runHistory` peer, clock `now`/`sleep`, and structured `signal` cancellation. Runs, and checks what each step leaves |
| `examples/library.mts` | The app's library system ported handler for handler. Typechecks against stand-ins for its imports; not run |
| `examples/threads.mts` | Three backend systems, a state per thread, and two windows: asks, tells, a reply the thread writes and broadcasts, windows that leave part-way, and a refusal that carries data. Runs, and checks what each step leaves |
| `examples/views.mts` | A surface following views, modelled on the threads surface: one always, one while a thread is open, one per tab. Runs, and checks what is followed after each step |
| `tools/graph.mts` | Derives each state's graph from its types, running nothing: one file's printed (`npx tsx tools/graph.mts <file>`), or every example's written to and checked against `etc/graphs/` (`graph:update`, `graph:check`) |
| `etc/graphs/*.txt` | Each example's graph, as the tool reads it |
| `surveys/xstate-survey.mts` | The survey of how the app uses XState that the plan's figures come from |

Every check runs with `npm test`, each file a spec and each check a case. One file, or the cases named with some
words:

```bash
npx vitest run draft
```

```bash
npx vitest run -t "under every ordering"
```

An example runs on its own too:

```bash
npx tsx examples/threads.mts
```

The component `vue-tsc` checks:

```bash
npx vue-tsc --noEmit -p type-tests/vue-templates/tsconfig.json
```
